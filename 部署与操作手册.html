AegisOps 2026.11.18 部署与操作

发行版只需选择 Windows、Linux、源码三个包之一。首次部署自行创建管理员，没有默认账号密码；发行包不包含业务数据库、会话、设备凭据或模型密钥。

Windows 10/11 x64

  1. 将 Windows ZIP 完整解压到普通用户可写的目录，建议使用短路径。
  2. 双击 start.cmd。基础 Python 和 Git 随包提供，首次启动会下载 Node、Python 运行依赖和场景编译依赖；请保持网络可用并等待控制台提示。
  3. 缺少 Microsoft Visual C++ x64 运行库时，会调用随包的微软安装器，请完成系统安装提示。
  4. 安装中断后重新运行同一目录下的 start.cmd，已校验的下载可复用。完成后日常启动使用本地依赖。
  5. 浏览器打开 http://127.0.0.1:5200，设置自己的管理员账号密码，再配置模型和设备。

可在命令行执行：

start.cmd --check
start.cmd --port 5201
start.cmd --data-dir D:\AegisOpsData

默认数据目录为项目内 runtime；日志为 runtime\logs\windows-server.log。保持启动窗口打开，使用 Ctrl+C 停止。依赖仅安装到项目的 _runtime 目录，不覆盖系统 Python。

Linux / WSL2

要求 Python 3.12、Node.js 20+、npm、Git，以及联网安装依赖的能力。解压 Linux 或 Source 包，在项目目录运行：

bash install.sh
.venv/bin/python run.py --host 127.0.0.1 --port 5200 --data-dir /path/to/aegisops-data

以安装脚本最终提示为准。WSL 建议把项目解压在 Linux 文件系统中。指定固定的数据目录，更新时继续使用该目录。

Docker

docker compose up -d --build

沿用 Compose 数据卷，不执行删除数据卷的操作。更新时重新构建镜像并复用原卷。本次验证覆盖 Linux 原生和 Windows 本机部署，未重新构建 Docker 镜像。

首次使用

  1. 首次访问页面，创建管理员；在账号管理里新增成员并分配所需场景权限。
  2. 在模型清单中添加实际供应商与 API 配置，设置默认模型；密钥由部署者手工填写。
  3. 按需要接入态势感知设备。支持直接手动配置，也可把厂商 API/配置手册与脱敏日志交给 Atlas 协助；非预置设备需要按真实样本完成连接器和工作流适配。
  4. 从场景中心切换研判、漏洞运营、应急响应和威胁情报。

威胁情报与资产核查

点击“同步最新情报”会由本平台直接访问七家官方来源，不再下载第三方项目的公开数据库。首页按来源展示，进入后使用关键词、等级和日期范围筛选。个别来源暂不可用时保留历史记录，并显示失败状态。

在漏洞运营中维护资产，并在产品与版本页登记真实软件版本。点击“Atlas 核查”可结合原生对话、只读查询工具和官方公告核对风险。关键词匹配只产生候选线索；缺少版本或配置依据时不会自动确认漏洞。核实后可转入漏洞整改、复测和历史归档。

每日更新默认关闭。在情报页面开启后，由任务中心运行 aegis-threat-daily 工作流：官方直采 → 增量入库 → 近30天资产产品匹配。个别来源失败继续其他来源；全部失败则停止本轮匹配。任务不会自动确认漏洞或主动扫描资产。

应急响应

可从确认告警转入，或手工创建事件。正式告警沿用实际来源设备；手工事件需明确选择设备。先登记受管主机，SSH 使用可信公钥，Windows 使用 WinRM HTTPS 与可信证书。

点击授权 AI 调查后，执行受限基础采集，并在 Linux SSH 调查中调用 Solar 固定官方版本作为辅助采集工具。原始包、文本报告、清单与 SHA-256 归档到事件；AI 继续关联证据与追查，结果进入报告弹窗供人工复核。权限、网络或采集失败会写入过程记录，不会宣称已完成。

Windows 当前使用 WinRM 固定模板，不后台执行 Solar 图形界面工具。远程调查不是无痕操作，会产生登录和采集活动；不自动执行样本、删除或修复文件。

REA 与样本分析

主包不携带 REA、Ghidra、JDK 离线环境。未安装时，在样本区域点击安装入口，由 Atlas 协助发起已授权的固定安装任务，查看实际进度和日志，通过环境自检后才能使用。

本机隔离 REA worker 需要 Linux x64 / WSL2 及所需系统权限。原生 Windows 用户可使用 WSL2 部署 Linux 后端；当前不宣称支持原生 Windows REA worker。微步和 VirusTotal 支持哈希查询及明确确认后的样本上传，也保留官方网页入口。

更新与备份

在账号管理的在线更新区检查新版本。托管启动的安装包在兼容性检查通过后，可以下载、校验、备份并更新；开发运行或 Docker 使用手工部署方式。2026.11.18 保留上一版核心依赖锁文件，避免仅因本次业务功能更新强制更换已有依赖。

手工更新时，停止旧服务，备份完整数据目录，将新包解压到新目录，以相同 --data-dir 启动。Windows 首次启动会检查自身私有依赖。不要用空白目录覆盖已有数据，也不要同时启动两个写入同一数据目录的实例。

故障检查

  • 页面未显示：检查 /api/health、端口占用和启动日志；场景首次编译需等待。
  • 初次下载中断：保持目录不变重跑启动器，查看失败包与网络信息；不删除业务数据来修复依赖。
  • 情报单源失败：查看该来源错误和最近成功时间；历史记录仍保留。
  • 取证未完成：查看事件过程记录，核对主机、权限与证书，不绕过校验。
  • REA 显示未就绪：查看安装任务日志与实际环境状态，排队或命令结束不等于安装成功。

本次发行没有对真实业务主机执行远程调查，也没有使用用户企业沙箱权限做外发测试。发行测试、界面演示和实际业务采集的范围分别记录在发行验证文档中。
