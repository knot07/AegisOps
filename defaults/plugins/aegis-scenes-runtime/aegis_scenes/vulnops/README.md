# VulnOps · 安全漏洞运营系统

围绕“漏洞整体情况”和“漏洞整改情况”实现的单组织运营系统。提供真实数据库、登录、角色权限、证据附件、操作审计与完整整改闭环。界面为中文，所有图表从当前数据库计算。

## 开始使用

1. 双击本目录的 **start.cmd**，浏览器会打开 **http://127.0.0.1:8765**。
2. 首次进入时创建管理员账号，密码至少 10 位。没有预设账号或默认密码。
3. 在“成员与权限”创建整改负责人，必要时再创建安全运营人员。
4. 在“资产目录”添加业务系统、地址、部门和重要性。
5. 在“漏洞台账”登记漏洞并分派责任人。

本机已准备运行环境。将源代码 ZIP 解压到其他电脑时，需要 Python 3.11+ 或 uv；首次启动需要联网安装依赖。推荐 PowerShell 7，启动脚本在未安装 PowerShell 7 时兼容使用 Windows PowerShell。

不要直接双击 static/index.html，页面需要通过后台服务访问。启动窗口保持打开；关闭服务可按 Ctrl+C，或双击 **stop.cmd**。数据会保留，下次启动继续使用。重复运行启动脚本会识别已经运行的服务。

需要改端口时，在本目录执行：

```powershell
pwsh -File .\start.ps1 -Port 8877
pwsh -File .\stop.ps1 -Port 8877
```

## 功能与页面

| 页面 | 已实现能力 |
| --- | --- |
| 运营总览 | 累计漏洞、未关闭高危/严重、逾期、待复测、风险分布、近 14 天趋势、关闭率、平均关闭周期、部门进展、优先跟进 |
| 漏洞台账 | 登记、修改、按名称/编号/资产/CVE 搜索、风险等级与状态筛选、责任人/我的漏洞/逾期筛选、分页、CSV 导出 |
| 漏洞详情 | 资产归属、发现日期、整改期限、描述、影响位置、修复建议、证据附件、完整处理时间线 |
| 整改工作台 | 分派、转派、开始整改、提交复测、复测通过、复测退回、重新打开、补充记录 |
| 资产目录 | 登记业务资产、记录地址与所属部门、查看关联漏洞和未关闭数量 |
| 成员与权限 | 创建四种角色账号、启用/停用账号、自助修改密码 |
| 操作审计 | 查询登记、修改、分派、整改、复测、登录、导出、成员变更等操作及处理说明 |

CSV 使用 UTF-8 BOM，方便 Excel 打开，导出遵守当前筛选与权限范围，并处理公式注入前缀。证据附件支持图片、PDF、TXT/LOG、CSV、DOCX、XLSX、ZIP；单文件最大 10 MB。附件统一通过鉴权下载，不在网页内执行。

## 整改闭环

```text
登记漏洞 → 待分派 → 分派责任人 → 待整改 → 开始整改 → 整改中
                                   └──────────────┬──────┘
                                                  ↓
                                            提交整改 / 待复测
                                                  ↓
                              ┌───────────────────┴───────────────────┐
                         复测未通过                                复测通过
                              ↓                                       ↓
                            整改中                                  已关闭
                                                                      ↓
                                                               发现复发 → 重新打开
```

- 登记时已选择责任人，会直接进入“待整改”。待整改也可直接提交复测。
- 提交整改时必须填写实际处理说明。可以在提交前上传整改证据。
- 只有安全运营或管理员可以分派、复测或重新打开。
- **整改提交人与复测人必须是不同账号。** 即使提交人为管理员，也不能自审。
- 复测通过必须记录验证结论；复测失败退回“整改中”，所有历史记录保留。
- 待复测期间不能转派。需要退回整改后再转派。
- 已关闭漏洞需要先重新打开，才能编辑基础信息。
- 重新打开保留原期限；原责任人已停用时回到“待分派”。
- 不提供直接删除漏洞或审计记录的页面操作，避免破坏整改追溯链。

## 数据口径

| 指标 | 计算方式 |
| --- | --- |
| 累计漏洞 | 当前用户权限内全部已登记记录 |
| 未关闭漏洞 | 状态不是“已关闭”的记录，包含待复测 |
| 未关闭高危/严重 | 未关闭漏洞中风险等级为高危或严重的记录 |
| 逾期 | 未关闭且整改期限早于今天；截止日当天不算逾期 |
| 关闭率 | 当前已关闭数量 ÷ 累计漏洞数量 |
| 平均关闭周期 | 当前已关闭记录的“关闭日期 − 发现日期”的平均天数 |
| 部门进展 | 按资产所属部门聚合 |
| 趋势 | 按发现日期计算新增，按当前关闭日期计算关闭；重新打开后不计入关闭序列 |

业务日期统一按北京时间；操作时间以 UTC 存储，页面按北京时间显示。空数据不会显示虚构指标。

不手工填写整改期限时，使用默认 SLA：严重 1 天、高危 7 天、中危 30 天、低危 90 天，从发现日期起计算。修改期限必须填写变更原因，审计记录保留修改前后值。期限也可以手工设置，用于适配本组织制度。

## 权限设计

| 能力 | 管理员 | 安全运营 | 整改负责人 | 只读观察员 |
| --- | --- | --- | --- | --- |
| 查看漏洞、统计、附件和导出 | 全部 | 全部 | 仅分配给自己 | 全部 |
| 登记/修改/分派漏洞、登记资产 | 可以 | 可以 | 不可以 | 不可以 |
| 开始整改/提交整改/上传证据/补充记录 | 可以 | 可以 | 仅自己的漏洞 | 不可以 |
| 复测、重新打开 | 可以 | 可以 | 不可以 | 不可以 |
| 查看全局操作审计 | 可以 | 可以 | 不可以 | 不可以 |
| 创建/启停成员 | 可以 | 不可以 | 不可以 | 不可以 |

为方便协作，已登录用户可查看成员和资产基本目录。整改负责人的资产漏洞数量仍只统计自己可访问的记录。停用有未关闭漏洞的成员前，必须先转派；不能停用当前登录账号。

权限从登录会话和数据库中的账号角色取得，由服务端代码判定。客户端不能通过提交角色、用户身份或状态字段提升权限。会话使用 HttpOnly、SameSite=Strict Cookie，有效期 8 小时；修改密码或停用账号会撤销已有会话。密码使用 PBKDF2-SHA256 加随机盐保存。并发修改使用版本号检查，旧页面覆盖新记录会被拒绝。

## 持久化、备份与恢复

```text
data/
  vulnops.db          SQLite 数据库（用户、会话、资产、漏洞、时间线、附件索引）
  attachments/        随机文件名存储的证据附件
backups/              本地备份 ZIP
```

双击 **backup.cmd**，或者执行：

```powershell
.\.venv\Scripts\python.exe .\backup.py
```

备份脚本使用 SQLite 快照，同时打包数据库引用的附件；短暂阻塞写操作，防止数据库与附件索引不一致。备份副本会清除会话，恢复后需要重新登录，在线系统当前会话不受影响。

恢复方法：先停止服务，将当前 data 目录另行保留，再把备份 ZIP 内的 data 目录完整恢复到项目目录，然后重新启动。不要仅覆盖运行中的数据库文件，也不要将旧的 WAL/SHM 文件混入恢复目录。备份包含实际业务数据，应保存到受控位置。

## 技术结构

- 后端：Python 3.11+、FastAPI、Uvicorn。
- 数据库：SQLite WAL，事务写入、参数化查询、外键约束。
- 前端：原生 HTML/CSS/JavaScript，无 CDN、无需 Node 构建，不依赖外部字体或服务。
- 主要表：users、sessions、assets、vulnerabilities、events、attachments、attempts。
- 主代码：app.py；界面：static/；集成测试：tests/test_system.py。
- 健康检查：GET /api/health；其余业务接口需要登录。
- 可用环境变量：VULNOPS_PORT（端口）、VULNOPS_DATA（数据目录）、VULNOPS_SECURE_COOKIE（HTTPS 下设为 1）、VULNOPS_OPEN_BROWSER（启动后打开浏览器）。

本版本是**本机运行、单组织使用**的完整核心业务版本，服务默认只监听 127.0.0.1。尚未包含企业统一登录、邮件/企业微信通知、扫描器自动接入、误报归档、风险接受审批和多人跨机器部署配置。逾期提醒目前体现为系统内看板与筛选。需要正式内网部署时，应根据实际域名配置 HTTPS、允许的 Host、会话设置和数据库运行方式。
