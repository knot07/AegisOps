# TDP 固定研判工作流

该工作流用于TDP 单设备网络侧告警研判。工作流由 Python 固定执行，不允许模型自行选择查询接口。

## 固定步骤

1. 校验攻击源、告警时间、调查范围和研判轮次。
2. 查询告警前后 15 分钟的实时监控与 attack/risk/action 原始日志；三类日志分批取代表样本，输出截断时自动使用精简字段重试；设备不提供实时监控 API 时由同窗原始日志自动接管证据覆盖。
3. 查询智能聚合事件；证据不足或二次研判时扩展到前后 60 分钟。
4. 对匹配事件查询攻击成功统计、时间线、结果分布、受攻击实体、攻击者详情和关联告警；关联告警按小批次读取，避免大结果被截断后遗漏请求/响应包。
5. 规则引擎固定提取扫描强度、目标数、端口数、信誉、白名单、利用与后渗透证据，并生成可执行的分级处置建议。
6. 从原始记录优先提取 `flow_src/dest`、协议和双端端口；按 TDP 语义将 `direction=out` 归一化为内到外，避免把威胁端角色字段误作真实包方向。
7. 默认模型只分析脱敏后的结构化证据并补充理由，不得覆盖规则确定的结论分类和处置等级；模型不可用时使用规则结果。
8. 最终节点应用硬限制并将结论写入 `datang_tdp_v2.db`，看板自动同步。

## 安全边界

- 只调用 TDP 只读查询工具。
- 不执行封禁、阻断、隔离或设备配置修改。
- 不保存完整 raw_data、Cookie、Token、Secret 或大段 Base64。
- HTTP 200、established、is_connected、TDP success 均不能单独证明攻击成功。
- established=true 只表示 TCP 可达，threat.is_connected=0 表示 TDP 未判定恶意连接成立，两者不作为矛盾证据。
- 扫描类处置区分白名单、低频观察、24-72 小时临时封禁/限速与永久封禁，不输出空泛建议。
- 扫描器告警若全部处于 recon/scan/discovery 阶段且没有利用载荷或后渗透证据，保持“疑似扫描”；3 次及以上重复探测建议 24-72 小时临时封禁或限速。
- 明确漏洞利用与 C2/木马连接尝试可在未确认攻击成功时给出临时封禁建议，但不得据此判定主机失陷。
- 可信公共 DNS/CDN/共享基础设施 IP 携带恶意域名 IOC 时，结论降为“证据不足”，仅临时阻断域名，不得连带封禁该 IP。
- 银狐、黑产团伙、C2、木马等出站告警携带域名 IOC 时，固定判为“恶意外联”，在 DNS、安全代理或出口防火墙的出站规则阻断域名，不得把聚合公网 IP 当成入站攻击源封禁。
- 目的端口为 53 不能单独证明 DNS 隧道；缺少可核验的 QNAME/载荷特征与稳定周期性证据时，禁止输出 DNS 隧道归因。
- 扫描类按统一阈值处置：已确认境内且低于 3 条记录、3 个目标和 10 个目标端口、无强恶意信誉时转人工复核，不直接放行或自动封禁；spam、scanner、云主机只作为弱风险上下文。达到任一批量阈值或命中明确恶意、黑名单、僵尸网络强信誉时，建议临时封禁或限速 24-72 小时。
- 明确识别为境外的公网源 IP 若已被 TDP 检出攻击或扫描行为，不受上述低频观察阈值限制，建议仅对该单一 IP 临时封禁或限速 24-72 小时；地理位置未知时不得猜测，白名单、CDN、公共 DNS、共享基础设施和出站域名告警不适用此规则，也不得自动扩大到 ASN 或网段。
- 同类扫描按 15 分钟窗口跨源 IP 聚类：达到 5 个源 IP，或同一目标达到 3 个源 IP，即判定为分布式扫描活动。此时即使单 IP 仅出现一次，也建议临时封禁/限速已观测源 IP 并启用 WAF/IPS 行为策略，但不扩大封禁整个云厂商 ASN 或网段。
- 无后渗透证据闭环时不允许输出“已失陷”。
