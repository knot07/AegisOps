# AegisOps 2026.11.11

本次在 2026.11.08 基础上完善应急响应的真实调查能力、证据链及样本分析，并统一场景界面。

## 应急响应与证据

- Atlas 读取实际采集的进程、网络连接、登录、持久化及文件线索，最多三轮只读追查与自动取证；模型决策、工具返回及失败原因均留痕。
- Linux SSH 校验主机指纹，Windows WinRM 使用 HTTPS；只允许登记且匹配事件目标的主机。文件取证比较远端和本地 SHA-256，不执行恶意文件。
- 事件状态支持开始调查、提交复核、退回调查、归档及重新打开；填写处理说明，防止旧状态覆盖，归档后禁止继续修改证据，重新打开后可继续调查。
- 六个实际功能入口：调查动态、设备关联、主机排查、样本与逆向、沙箱分析、响应报告。取证区增加分类、计数和搜索，报告使用 Markdown 详情弹窗。

## 来源设备绑定

- 告警转应急时记录实际告警来源设备；手工事件必须明确选设备，旧事件通过“明确来源设备”补充，来源变更保留审计及历史证据。
- 当前自动日志适配支持 TDP 与 360 WAF v5.5。其他设备可登记但明确标注待适配，不会悄悄改查默认设备。360 WAF 查询最多 500 条，覆盖范围明确为部分数据。
- 场景更名“态势感知 AI 研判”；来源设备选择加入厂商 Logo、柔和主题、键盘操作和清晰选中状态。

## 样本分析与 REA

- 源码类样本调用模型静态审阅；PE/ELF 可使用 REA 6.8.0 + Ghidra 12.1.4，取得真实函数、伪代码及调用关系；报告标注已覆盖范围及部分完成状态。
- REA 通过平台原生工具 incident_sample_reverse 和 rea-malware-reverse 技能调用。自动深度逆向仅支持 5 MB 内 PE/ELF，最多两轮、六个附加静态查询。
- Linux 包包含可选 REA 离线环境（Node / JDK / Ghidra / Python 依赖），需 root、Linux x64/WSL2、Python 3.12 和网络命名空间；静态解析使用低权限账户、无外网命名空间。详见 docs/REA.md。
- 原生 Windows 提供工作台、静态特征/源码分析和外部平台接口，**不提供原生 REA/Ghidra 环境**；需要深度逆向时请在 WSL2 部署 Linux 包。未增加动态沙箱或 EDR。
- 微步云沙箱和 VirusTotal 支持哈希查询、确认后的文件上传、结果归档和详情查看；上传回执不当成分析结论。复用工具清单的密钥；标准 VT 上传可能共享样本，敏感文件不应提交。
- 两个平台均提供官网手动上传入口；微步使用柔和珊瑚红、VT 使用靛蓝配暖白渐变。

## 漏洞运营与界面

- 管理员支持复测自己的整改提交，普通安全成员仍不能自审。复测通过可归档到“已整改的历史漏洞”，保留时间线与证据。
- 合并重复的整改工作台与漏洞台账，旧入口兼容跳转，原有分派、整改、复测等能力保留。
- 资产关联、拓扑流光动画、场景与导航 Logo、详情按钮、字体、日历、工作台和品牌主题统一。

## 部署、升级与验证

仅选择一个主包：Windows-x64.zip（原生 Windows 附运行时）、Linux.zip（Linux/WSL2，含可选离线 REA）、Source.zip（完整源码和已构建前端，不含 REA 大型运行时）。首次启动由用户设置管理员，无默认账号；不含现有业务数据、设备密码、API Key 或取证样本。

旧版本升级前备份数据，停服后在新目录解压并使用原 --data-dir。通过 run.py / start.cmd 托管的在线更新会校验、备份并保留数据；用户改动过的插件文件不会自动覆盖，需对比合并。Docker 请重新构建并复用数据卷，REA 隔离环境需额外部署。

受控 Linux 靶场已验证真实 SSH 采集、源/本地哈希一致、Atlas 调查及 REA 反编译。WinRM 和企业设备连接仍需在用户授权环境验证；模型结论需人工复核，不承诺准确判断所有攻击或完整归因。本次未向微步或 VT 外发样本，外部接口验证使用隔离模拟响应。具体发行包启动及自动化验证结果见 docs/RELEASE-VERIFICATION.md。
