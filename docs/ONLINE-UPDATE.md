# 在线更新

管理员可在侧栏底部的语言、主题等小图标旁找到更新入口。普通用户不显示该入口，后端同样校验管理员权限。没有定时公告或自动安装。

1. **检查更新**：只读取 `knot07/AegisOps` 最新稳定 Release，展示版本和发行说明。
2. **下载并校验**：下载该仓库的 Source 包，校验 GitHub 提供的 SHA256 与包内逐文件清单，拒绝不安全路径、降级与依赖不兼容。
3. **备份并安装**：等待运行中的对话与应急任务结束，确认后停止服务，备份代码与业务数据，再替换发行文件。保留用户自行修改的插件。
4. **启动检查**：新版健康检查通过后完成；失败则恢复代码和数据并重新启动旧版。窗口在重启期间会短暂断开。

默认数据不清空。备份在数据目录 `updates/backups/`，包含敏感业务信息，应受控保存。已被本地修改的发行文件可能使完整性检查失败，这时应走手工迁移，保留自定义差异。

自动安装要求使用新版 `run.py` / Windows `start.cmd` 托管启动。开发环境和 Docker 仅支持检查版本及查看发行版；Docker 请重建镜像并复用原数据卷。Python 或 npm 依赖锁定文件变化时，系统要求下载完整包更新，避免在现有运行环境中直接变更依赖。

2026.11.06 及更早版本没有此更新入口，需先手工升级至 2026.11.08。首次升级先停止服务并备份原数据目录，在新目录解压新包，指定同一个数据目录启动。不要覆盖或删除数据目录。

SHA256 用于确认下载及文件完整性，依赖 GitHub 发布权限与 HTTPS 信任，并非独立的离线代码签名。离线环境使用完整包手工升级。
